# Demo-seed (emt_showcase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** детерминированный demo-seed для `emt_showcase`: изолированная демо-база с ~800 нарядами за полгода,
реалистичным каталогом и пятью hero-сущностями со стабильными ID, плюс verify, который сверяет сид с
настоящим кодом приложения.

**Architecture:** чистые генераторы (`demo/seed/generators/*`, без БД) собирают `DemoPlan` из
`DEMO_NOW` и детерминированных потоков faker. Тонкий writer пишет план через сервисы приложения
(каталог, клиенты, машины, резервы, настройки), а наряды со строками вставляет пачками в одной
транзакции. Суммы считает настоящий `PricingService`, цены строк — `PriceResolutionService`. Свой
Nest-контекст `DemoSeedModule` поднимается без `SeedModule` и `AuthModule`. Verify
(`seed:demo:verify`) прогоняет `WorkOrdersCoreService.recompute` и `previewTemplate` по всей базе и
после себя ничего в ней не меняет.

**Tech Stack:** NestJS 10, TypeORM 0.3, PostgreSQL 16 (docker), ts-node, jest + ts-jest,
`@faker-js/faker` 9.9.0 (`ru`), Playwright (из `client/`) для скриншотов.

**Spec:** `docs/superpowers/specs/2026-11-04-crm-showcase-design.md` — раздел 2 целиком, из раздела 1 —
`demo/seed/` и `docker-compose.demo.yml`.

## Global Constraints

- Все пути указаны от корня `emt_showcase` (раскладка как у `emt_service`). Remote `upstream` → `emt_service`.
- Изменения только аддитивные. Исключения, без которых не обойтись: `package.json` (4 скрипта +
  devDependency), `package-lock.json`, `tsconfig.build.json` (`"demo"` в `exclude`). Файлы `src/` и
  `client/src/` **не трогаем**.
- `@faker-js/faker` — devDependency **ровно `9.9.0`** (`--save-exact`). Ветка 10.x поставляется только как
  ESM, и ts-node в режиме CommonJS её не подключит. В runtime-образ faker не попадает (`npm ci --omit=dev`).
- Прогон сида: `npm run seed:demo` → `ts-node demo/seed/demo-seed.ts [--force] [--now=YYYY-MM-DD]`.
  Проверка: `npm run seed:demo:verify` → `ts-node demo/seed/verify.ts`.
- Отказ, если `NODE_ENV=production`, если `DATABASE_URL` не задан явно в окружении, если имя БД не
  содержит `demo`, если база непустая без `--force`. Для сида обязателен `DEMO_PASSWORD`.
- Сброс: `TRUNCATE … RESTART IDENTITY CASCADE` по всем таблицам сущностей, кроме `vehicle_generations`
  (таблица `migrations` не сущность и в список не попадает). Затем
  `ALTER SEQUENCE work_order_doc_number_seq RESTART` и `ALTER SEQUENCE work_order_order_number_seq RESTART`.
- Детерминизм: seed `42`, `setDefaultRefDate(DEMO_NOW)`. `DEMO_NOW` = день из `--now` (по умолчанию
  сегодняшний день по Москве), время **12:00 MSK**. Все UUID и `group_key` выдаёт `demoId()`.
- Время везде московское, фиксированный сдвиг **UTC+03:00** (переходов нет с 2014 года). Локальные методы
  `Date` (`getHours`, `setHours`, `getDate`, `getDay`…) и часовой пояс хоста не используем.
- Объёмы: сотрудники — 1 `owner`, 2 `master_receptionist`, 3 `master`; клиентов 150, из них 15 юрлиц;
  машин ~200, MINI ~80%; работ ~60, деталей ~150; нарядов ~800 (6 мес. до `DEMO_NOW` + 14 дней вперёд).
- Ставка: `rate_snapshot` = 2000 до (`DEMO_NOW` − 3 календарных месяца, 00:00 MSK) и 2200 после;
  `labor_rate` = `2200`.
- Госномер `^[АВЕКМНОРСТУХ]\d{3}[АВЕКМНОРСТУХ]{2} \d{2,3}$`; VIN `^[A-HJ-NPR-Z0-9]{17}$`, у MINI
  начинается с `WMW`; телефон `+7 (555) ddd-dd-dd`. Реальных персональных данных нет.
- `numericTransformer` превращает `undefined` в `NULL`, поэтому `total_cached`, `paid_amount`,
  `rate_snapshot`, `unit_price`, `qty`, `imported_deals_sum` всегда задаются явно.
- Демо-стек: контейнер `tatarin_demo_pg`, порт **5545**, БД `tatarin_demo`, `crm/crm`; api на **3100**,
  web на **8088**. Dev-базу `tatarin_pg` (:5544) не трогаем никогда. Если docker недоступен, подойдёт любой
  Postgres 16 с базой `tatarin_demo`: guard проверяет только имя БД.
- Тесты — обычный jest с рукописными фейками (`as never`), без `@nestjs/testing` и supertest.
- prettier не запускать. Стиль — как в `src/`: одинарные кавычки, 2 пробела.
- Полный набор проверок после каждой задачи:
  `npx tsc --noEmit && npm test && npm run lint -- --max-warnings=0 && npm run build && npm run test:demo && npm run lint:demo -- --max-warnings=0`.

## Review Focus

1. `DATABASE_URL` не задан явно, а в `.env` лежит dev-база, или `demo` встречается только в хосте, логине
   либо query (`postgres://demo@demo-host/tatarin_crm?application_name=demo`). Сид должен отказать
   **до** импорта `src/data-source` (там `dotenv` молча подхватит `.env`). Тесты — задача 2.
2. В базе уже есть данные, а флаг передан с опечаткой (`--froce`, `--now 2026-11-04` без `=`). Ожидаем
   отказ без единого `TRUNCATE`, а не тихий прогон с флагами по умолчанию. Тесты — задача 2, ручная
   проверка — задача 8.
3. Хост с часовым поясом не `Europe/Moscow` (CI в UTC, ноутбук в Лос-Анджелесе). План обязан совпадать
   до байта. Тест в задаче 7 переключает `process.env.TZ`.
4. `--now` на пятницу, воскресенье, последний день месяца или 29 февраля. Инварианты статусов и дат,
   плотный день и свободное окно должны сохраниться. Тест в задаче 7 прогоняет четыре даты.
5. `verify` сам пишет в базу: `recompute` трогает `total_cached` и `updated_at`, а для превью нужен
   пробный наряд. После verify отпечаток базы обязан совпасть с исходным. Ручная проверка — задача 9.

- [ ] **Step 4: Реализовать `ids.ts`, `time.ts`, `rng.ts`, `config.ts`**

`demoId` — name-based UUID (форма v5) без зависимости от порядка вызовов rng:
```ts
const h = createHash('sha256').update(`${DEMO_SEED}:${scope}:${key}`).digest('hex');
const variant = ((parseInt(h[16], 16) & 0x3) | 0x8).toString(16);
return `${h.slice(0, 8)}-${h.slice(8, 12)}-5${h.slice(13, 16)}-${variant}${h.slice(17, 20)}-${h.slice(20, 32)}`;
```
`time.ts` работает на `Date.UTC` и `getUTC*` от значения, сдвинутого на +180 мин. `makeFaker`:
`new Faker({ locale: [ru, en, base] })`, затем `.seed([DEMO_SEED, fnv1a32(stream)])` и
`.setDefaultRefDate(demoNow)`. У каждого генератора свой поток, поэтому правка одного генератора не сдвигает
данные остальных. `probit` — рациональная аппроксимация Acklam. `stratifiedLognormal` берёт квантили
`(i + u_i)/n` при `u_i = f.number.float()`, получает `exp(ln(median) + sigma·probit(q))` и перемешивает
результат через `f.helpers.shuffle`. `ids.ts`, `time.ts` и `config.ts` не импортируют faker, `@nestjs/*`
и `src/`.

Остальное раскладывается по `dailyCounts(demoNow, ORDERS_TARGET − закреплённые)`. На `busyDay` нарядов
добавляется столько, чтобы в сумме было ≥ 9. В следующий будний день ≥ 4 наряда, и все они вне
`freeSlot`. Для каждого слота клиент выбирается `weightedIndex` с весом `REGULAR_WEIGHT` для `regular` и 1
для остальных, причём кандидаты — только клиенты с `created_at` ≤ даты создания наряда. Затем выбирается
его машина. Целевой чек — `stratifiedLognormal` по месяцу с медианой
`TICKET_MEDIAN × (1 + MONTHLY_TICKET_GROWTH)^monthIndex`. Работы набираются так:
```text
picks = []
while sum(estimate(picks)) < 0.9·target and picks.length < 6:
  pool = работы не из picks, с estimate ≤ (target − sum)·1.5 + 1000,
         вес = task.weight × (tires && месяц ∈ {10,11} ? 6 : 1)
  if pool пуст: break
  picks.push(weightedIndex(pool))
if picks пуст: picks = [самая дешёвая работа по весу]
```
`estimate` = цена работы для поколения машины + сумма её default-деталей. Длительность =
`clamp(roundUp30(Σ hours × 60), 30, 480)`. Мастер — `DayBoard.place`. Если места нет, наряд переносится на
следующий будний день, но не дальше конца окна.

**Статусы и даты** (`end = scheduled_at + duration`, возраст отсчитывается от `DEMO_NOW`):

| Условие | Статус |
|---|---|
| `scheduled_at > DEMO_NOW` | `scheduled` |
| `scheduled_at ≤ DEMO_NOW < end` | `in_progress` |
| `end ≤ DEMO_NOW`, возраст `end` ≤ 3 дн. | `closed` 30% / `done` 30% / `waiting` 20% / `in_progress` 20% (последний — только при возрасте ≤ 2 дн.) |
| возраст 3–7 дн. | `closed` 85% / `waiting` 10% / `done` 5% |
| возраст > 7 дн. | `closed` 96% / `done` (без оплаты) 4% |
| ровно 2 наряда с `scheduled_at` в `[DEMO_NOW − 2 дн., DEMO_NOW)` | принудительно `scheduled` (просроченные) |

`created_at` = `scheduled_at` минус 0–10 дней (чаще 1–3), в 10:00–19:00, но не позже

1. **staff** — `createUser`, затем `rekey('users', saved.id, plan.id)`.
2. **settings** — `SettingsService.set` по каждому ключу.
3. **catalog** — `TaskTemplatesService.create({ id, … })`; `PartTemplatesService.create` + rekey;
   `setPrice` + rekey; `attachPart` + rekey. Код поколения переводится в id через
   `SELECT id, code FROM vehicle_generations WHERE make = 'MINI'`. Если какого-то из 19 кодов
   `MINI_GENERATIONS` нет — ошибка.
4. **clients** — `ClientsService.create({ …, created_at })` + rekey (до создания машин).
5. **vehicles** — `VehiclesService.create({ client_id, vin, make, model ?? undefined, generation_id, plate, year, mileage })` + rekey.
6. **orders** — одна `ds.transaction`. Внутри: `SELECT nextval('work_order_doc_number_seq') AS n FROM generate_series(1, $1)`

8. **backdate** — одним `UPDATE … FROM (VALUES …)` на таблицу: `clients.updated_at = created_at`,

   `calendar_blocks.created_at` из плана.

`rekey(ds, table, from, to)` = `UPDATE "<table>" SET id = $2 WHERE id = $1` через `ds.query`. Сервисы
`id` не принимают, а на только что созданную строку ещё никто не ссылается. Сырой SQL не трогает
`updated_at`.

    — у закрытых номера 1..N подряд и строго растут вместе с `(closed_at, id)`; у прочих `null`.
  - `checkClosedTotals(rows: { status: string; total_cached: number; total_frozen: number | null; paid_amount: number; closed_at: Date | null }[]): string[]`
  - `checkDates(rows: { status: string; created_at: Date; scheduled_at: Date; closed_at: Date | null; updated_at: Date }[], demoNow: Date): string[]`
  - `diffPartSets(expected: { part_template_id: string; qty: number; is_default: boolean }[], actual: typeof expected): string | null`
  - `formatDistribution(byStatus: Record<string, number>, byMonth: { month: string; orders: number; revenue: number }[]): string`
  - `fingerprint(ds: DataSource): Promise<string>` — sha256 по всем таблицам из `tablesToTruncate`.
    Каждая таблица: `md5(string_agg(t::text, '|' ORDER BY t::text))`; у `users` без `password_hash` (bcrypt
    солит каждый раз).
  - `runVerify(app: INestApplicationContext): Promise<{ errors: string[]; fingerprint: string }>`

Что делает `runVerify` (каждая проверка добавляет строки в `errors`):
1. Читает `demo_now` из `settings`, вызывает `buildDemoPlan`, сравнивает **точные** количества по таблицам:
   `users`, `clients`, `vehicles`, `work_orders`, `labor_lines`, `part_lines`, `task_templates`,
   `part_templates`, `template_generation_prices`, `task_template_parts`, `calendar_blocks`, `settings`.
2. Ищет сирот. Должно быть 0: клиентов без машин, нарядов без строк, нарядов без мастера или с мастером
   не в роли `master`, строк деталей с `part_template_id`, которого нет в каталоге, строк работ с
   `template_id`, которого нет среди шаблонов.
3. Снимает снапшот `id, total_cached, updated_at` всех нарядов. Для каждого вызывает
   `core.recompute(id)` и сравнивает с исходным `total_cached`. В `finally` восстанавливает оба поля одним
   `UPDATE … FROM (VALUES …)`.
4. Прогоняет `checkClosedTotals`, `checkDocNumbers`, `checkDates`.
5. Свободное окно: ни один наряд и ни один резерв не пересекают `heroSchedule(demoNow).freeSlot`.
6. Детали шаблонов: создаёт пробные клиент, машину и наряд через сервисы (телефон `+7 (555) 999-99-99`).
   Для каждого поколения (и для `null`) выставляет `vehicles.generation_id` сырым `UPDATE`, затем для
   каждого шаблона вызывает `previewTemplate(probeWo, tplId, { id: ownerId, role: 'owner' })` и сравнивает
   через `diffPartSets` с `resolveTemplatePartsPlan`. В `finally` удаляет наряд, машину и клиента сырыми
   `DELETE`. Последовательности при этом не расходуются.
7. Печатает `formatDistribution` и метрики `stats.ts` (рост, сезонность, Парето). Ошибки здесь — только
   при выходе за пороги Task 7.

Отпечаток `fingerprint` снимается до проверок и после них. Если они разошлись, это ошибка: verify обязан
ничего не менять. Точка входа `verify.ts` устроена как `demo-seed.ts` (guard → динамический импорт),
печатает `fingerprint: <hex>` и завершается с `exit 1`, если `errors` не пуст.
