# Spec: CRM для СТО (MINI Cooper) — MVP

**Status:** Draft
**Author:** AI-generated (по discovery-созвону)
**Date:** 2026-06-13
**Version:** 1.1

## Problem

Сервис обслуживает ~200–300 постоянных клиентов, новые приходят редко. Работают один мастер + владелец, используется тяжёлая СТО-CRM, где половина функционала избыточна. Нужен максимально простой инструмент под фактический процесс: завести клиента и его машины, назначить работы на время, вести их по статусам и посчитать смету. Также нужно перенести существующую базу клиентов из CSV. Бухгалтерия ведётся отдельно (Тинькофф) — от системы нужны только цифры выручки.

## Goal

Владелец за минимум кликов заводит клиента → его авто → работу, видит все предстоящие работы в календаре, двигает их по статусам на доске, считает смету по нормо-часу. Существующая база заезжает из CSV. Система простая сегодня, но спроектирована так, что модули (бот, документы, отчёты, каталог) пристёгиваются без переделки ядра.

## Scope — In

- Воркфлоу: добавление клиента (ФИО, телефон, **источник**) → авто (VIN, несколько ТС на клиента) → работа по авто
- **Источник клиента**: вручную или из Telegram-бота (значение зарезервировано, сам бот — позже)
- Прикрепление запчастей к работе как строк сметы (название + цена), назначение времени работы
- **Импорт клиентов из CSV** (ФИО, телефон, дата создания, кол-во закрытых сделок, сумма закрытых сделок) с дедупом и сохранением исторических агрегатов
- Календарь со всеми предстоящими работами
- Канбан-доска: смена статуса работы перетаскиванием
- Расчёт сметы: нормо-час × ставка, ручная цена (override), фикс. цены для шаблонных работ
- Скидка **на уровне заказ-наряда** (% или сумма)
- Удобный поиск по базе (ФИО, телефон, VIN, госномер)
- **Заложенная расширяемость** (архитектурно, не как фичи MVP): запись через Telegram-бота, модуль документов (PDF), бухгалтерия/отчёты, каталог деталей, доп. роли/мастера

## Scope — Out (Non-Goals)

- **Генерация документов (PDF)** — заказ-наряд/акт. Вне MVP, но модель данных уже готова к рендеру из заказ-наряда → модуль добавляется без миграции
- **Подробный учёт запчастей** — склад, остатки, поставщики, дозаказ. Запчасть = только строка стоимости
- **Полноценная бухгалтерия** — Тинькофф; от системы только выгрузка выручки
- **Расчёт ЗП / выработка** — один мастер; данные по работам сохраняются, добавить можно потом
- **Учёт пробега во времени** — храним только текущий пробег
- **Несколько ролей/мастеров одновременно** — сейчас одна роль; структура (`users` + `role` + `assigned_master_id`) заложена под расширение
- **Несколько филиалов, клиентский портал**
- **Очереди/воркеры (Redis/BullMQ), полнотекстовый поиск, микросервисы** — на этом объёме не нужны (см. NFR)

## Users & Stakeholders

| Роль | Потребность |
|---|---|
| Владелец/мастер (одна роль в MVP) | Завести клиента/авто/работу, импортировать базу, видеть загрузку, считать смету |
| Клиент (косвенно) | В будущем — запись через бота (проставит источник `telegram_bot`), документы |

## Functional Requirements

1. The system shall создавать клиента с ФИО, телефоном и источником (по умолчанию `manual`).
2. The system shall привязывать к клиенту несколько ТС (VIN, модель/поколение, госномер, год, текущий пробег).
3. The system shall создавать работу (заказ-наряд) для ТС с назначенным временем и статусом (1 визит = 1 наряд с несколькими операциями).
4. The system shall добавлять в работу строки работ (название, нормо-часы) и строки запчастей (название, кол-во, цена).
5. The system shall считать строку работ как `нормо-часы × ставка`, с ручной ценой и фикс. ценой из шаблона.
6. The system shall применять скидку (% или сумму) **на уровне заказ-наряда** и считать итог.
7. The system shall отображать работы с временем в календаре (день/неделя).
8. The system shall менять статус работы перетаскиванием по колонкам: Запланирована → В работе → Ожидание → Готова → Выдана.
9. The system shall искать по ФИО, телефону, VIN, госномеру и открывать карточку из результата.
10. The system shall фиксировать ставку нормо-часа в строке (snapshot) и итог при закрытии, чтобы изменение настроек не меняло прошлые работы.
11. The system shall импортировать клиентов из CSV (ФИО, телефон, дата создания, кол-во закрытых сделок, сумма закрытых сделок), сохраняя дату создания и исторические агрегаты, с дедупом по телефону.
12. The system shall различать источник клиента (`manual` сейчас; `telegram_bot` — под будущий бот; `csv_import` — при импорте).

## Non-Functional Requirements

- **Performance:** ~300 клиентов — тривиально. Поиск через `pg_trgm`/`ILIKE`, < 100 мс с базовыми индексами. Спец-масштабирование под нагрузку не требуется.
- **Scalability (про расширяемость, не нагрузку):** модульный монолит NestJS; бизнес-логика в сервисах (контроллеры тонкие) → будущий бот/импорт переиспользуют те же сервисы; UUID + честные FK; статусы/ставка/роли — в enum/настройках.
- **Robustness импорта:** CSV в UTF-8 и CP1251, разделитель `,`/`;`, дата `ДД.ММ.ГГГГ` или ISO; телефон нормализуется (8→+7, убрать пробелы/скобки) для дедупа и поиска; битые строки пропускаются с отчётом.
- **Security:** в базе PII (имена, телефоны) — auth + HTTPS, без публичного доступа. Single-tenant.
- **Reliability:** ежедневный бэкап Postgres.

## Acceptance Criteria

| # | Criterion | Linked Req |
|---|---|---|
| AC-1 | POST клиента создаёт запись с `source=manual`, видную в поиске | FR-1, FR-12 |
| AC-2 | К клиенту можно привязать 2+ ТС, каждое со своим VIN | FR-2 |
| AC-3 | Работа с `scheduled_at` показывается в календаре на этот день | FR-3, FR-7 |
| AC-4 | Строки работ+запчастей считаются; итог = Σ строк − скидка наряда | FR-4, FR-5, FR-6 |
| AC-5 | Строка из шаблона подставляет преднастроенную цену/часы | FR-5 |
| AC-6 | Перетаскивание карточки в другую колонку меняет статус (persisted) | FR-8 |
| AC-7 | Поиск по части VIN/телефона/ФИО возвращает корректную запись | FR-9 |
| AC-8 | Изменение глобальной ставки не меняет итог закрытых работ | FR-10 |
| AC-9 | Импорт CSV создаёт клиентов с сохранённой датой и агрегатами; повторный импорт того же телефона не плодит дубли | FR-11 |
| AC-10 | Клиент вручную → `source=manual`; импортированный → `source=csv_import` | FR-12 |
